**1．先明确：怎样的“100%”可以追求**

需要区分三个命题：

| 命题 | 能否实现或验证 |
|---|---|
| 某个固定测试集全部成功 | 可以，已有实物研究做到 |
| 声明分布下，成功率具有很高的统计下界 | 可以，需要足够独立试验 |
| 真实物理系统在任何情况下永不失败 | 不能由有限训练或测试建立 |

例如，HIL-SERL 在多个固定操纵任务上报告了 **100/100 成功**。这是支持你研究方向的重要实证，但不意味着真实成功概率已经被证明等于 1。[HIL-SERL 原文](https://arxiv.org/html/2410.21845)

当冻结策略，在同一声明分布下进行 \(n\) 次独立试验且全部成功时，单侧 95% 精确成功率下界为：

\[
p_L=0.05^{1/n}.
\]

| 全部成功的试验数 | 成功率下界 |
|---:|---:|
| 100 | 97.05% |
| 299 | 约 99% |
| 2,995 | 约 99.9% |
| 29,956 | 约 99.99% |

这是精确二项置信界的零失败情形。测试中持续改权重、反复挑选初态或择时停止，不能直接套用这个公式。[NIST 官方说明](https://itl.nist.gov/div898/software/dataplot/refman2/auxillar/exacbino.htm)

因此，我建议把目标写成：

> **在明确的初始状态、扰动、时间和重试预算内，追求零观察失败；同时报告统计下界，并为局部安全与恢复机制建立条件性保证。**

即使“不考虑泛化”，同一个桌面上的摩擦、抓取偏差、标定误差和延迟仍会变化。你可以不要求跨任务泛化，但仍需要场景内的稳健性。

**2．这个方案有多合理，和已有工作有多接近**

总体骨架已有直接先例，因此研究价值需要落到具体机制与证据上。

| 工作 | 与你设想的联系 | 尚未覆盖的关键部分 |
|---|---|---|
| **Scaling Up and Distilling Down，CoRL 2023** | LLM 引导规划和探索，自动检测失败与重试，再蒸馏为 diffusion policy，并研究仿真实物迁移 | 学习式风险门控、动作条件动力学评估 |
| **SAGE，Findings of EMNLP 2026** | 学生不确定时查询冻结 VLM，通过在线 RL 和模仿吸收教师经验，部署运行学生 | 主要是离散任务，缺少机械臂接触与实物验证 |
| **RAX，2026** | 慢探索逐渐形成持久经验和自主执行程序 | 固化介质主要是程序，并非神经快策略 |
| **RPD，2025** | VLA 指导 RL 探索，训练更小、更强的专用策略 | 运行时快慢路由与可靠性校准 |

来源：[ScalingUp](https://proceedings.mlr.press/v229/ha23a.html)、[SAGE](https://aclanthology.org/2026.findings-emnlp.1000/)、[RAX](https://arxiv.org/abs/2610.22496)、[RPD](https://arxiv.org/abs/2503.05833)。

这里有两个特别重要的判断。

**你的“慢理解逐渐转成熟练操作”有明确的计算解释：把昂贵搜索摊销进快速策略。** 不必证明它复制了大脑学习过程，也能形成合理的研究方案。

**“换窗口遗忘”与“技能遗忘”需要分别处理。** 对话上下文、GRU/LSTM 隐状态属于运行时记忆；长期经验应沉淀进轨迹库、技能参数和检查点。换窗口不会抹除已保存的模型权重。仅增加 LSTM，不能独立解决长期经验持久化。

你提到的两项工作也确实相关：

- **Show-Harness** 支持用语义动作接口连接 VLM 与机器人，再通过 interpreter 落到受限的实际运动。它适合作为慢探索接口。[论文](https://arxiv.org/html/2609.10522v1)
- **SuperMimic** 支持交替学习动力学与通过想象轨迹优化策略。但其主要对象是人形运动跟踪；官方“零失败”覆盖的是确定性、无噪声仿真中的训练动作库测试，不能转述为实物操纵的 100% 保证。[官方项目及评估限定](https://supermimic.github.io/)

**3．对你三个具体问题的回答**

**① 末端输出用 action trunk，还是位移？**

这两个概念处于不同层级：

- action trunk / expert：**用什么网络产生动作**。
- 末端位移、关节角、速度、力矩：**动作表达什么**。

因此可以直接采用：

\[
\text{action expert}\longrightarrow
A_t\in\mathbb{R}^{H\times7},
\qquad
u_t=[\Delta p^B,\Delta\theta^B,g].
\]

其中平移 3 维、旋转增量 3 维、夹爪 1 维。这里 \(B\) 表示基座坐标系。

推荐的融合方式是：

| 路径 | 内部实现 | 最终接口 |
|---|---|---|
| 慢路径 | VLM 提出子目标或语义原语，规划器产生轨迹 | 同一末端动作序列 |
| 快路径 | ACT、flow 或 diffusion action expert | 同一末端动作序列 |
| 恢复路径 | 已验证的回撤、重观察、重新抓取程序 | 同一命令接口及控制模式 |

两条路径经过相同的约束检查和执行控制器。**不要直接平均“向左绕”和“向右绕”两条动作轨迹**，平均结果可能碰到中间障碍。动作多模态应通过候选选择或分布建模处理。[π₀](https://arxiv.org/abs/2410.24164)、[Diffusion Policy](https://arxiv.org/abs/2303.04137)

旋转也不能随意累加欧拉角。一个明确的约定是：

\[
p^{ref}=p+\Delta p^B,\qquad
R^{ref}=\exp([\Delta\theta^B]_\times)R.
\]

如果复用已有 VLA，必须保留它原本的动作单位、坐标系和控制周期，或训练显式适配器。

**② “大脑”需要多大？**

没有论文能根据目前尚未限定的任务，直接推出最优参数量。我的建议是：

- 慢 VLM：先比较 **3–8B**，以冻结的约 **7B** 模型起步。
- 快策略：先用 **约 20–30M 的专用模型**，同时保留 ACT、Diffusion Policy 作为强基线。
- 更大的模型：只有在子目标选择、异常解释等独立评测确实不足时再增加。

单场景中，控制接口、数据覆盖、观察频率和恢复能力，可能比语言模型大小更直接地影响成功率。SmolVLA 也说明较小模型与异步执行值得认真比较。[SmolVLA](https://arxiv.org/abs/2506.01844)

**③ gate 怎样决定调用位移策略还是 VLA？能否调用 VLA 就奖励 +0.1？**

建议让 gate 选择三个 **option，即持续一段时间的闭环控制过程**：

\[
m_t\in\{\mathrm{FAST},\mathrm{SLOW},\mathrm{RECOVER}\}.
\]

它需要回答：

> 在当前状态历史、任务阶段和不确定性下，哪种控制过程最可能在预算内成功？

这比判断“这张图以前见过没有”更准确。相同 RGB 画面可能对应不同的滑移、接触力或夹持状态。Options 和 Option-Critic 提供了相应的形式化基础。[Options](https://doi.org/10.1016/S0004-3702(99)00052-1)、[Option-Critic](https://arxiv.org/abs/1609.05140)

**不建议给“调用 VLA”固定加 0.1。** 这种奖励会改变目标，甚至鼓励反复调用或拖长轨迹。希望偏好快速执行时，应直接计入实际耗时、计算成本和切换成本；可靠性优先时，则先满足风险约束，再优化速度。

还有一个容易忽略的实现问题：**不能为了判断是否调用慢模型，每次先运行一遍慢模型。** 应由轻量 critic 先估计慢 option 的价值，仅在值得调用时触发 VLM，再检查它生成的候选。

**4．推荐架构与具体计算**

以下是一套可实现的参考配置，并非最优配置证明。

| 模块 | 结构 | 约参数量 |
|---|---|---:|
| 慢规划器 | 冻结 7B VLM，输出结构化子目标，事件触发 | 7B |
| 快感知 | 双相机共享去分类头 ResNet-18，两路各投影到 256 维 | 约 11.4M |
| 本体融合与记忆 | 本体 MLP、融合 MLP、GRU-256 | 约 0.9M |
| 快动作 expert | 8 层 Transformer，宽 256，8 heads，FFN 1024，self/cross attention | 约 9M |
| 动作条件预测器 | 5 个独立 MLP ensemble，含物理辅助头 | 约 4M |
| Gate 与价值头 | 双 Q MLP，约 \(400\to128\to128\to3\) | 约 0.2M |
| 长程记忆 | 任务图、对象状态、事件日志与技能版本 | 首版采用结构化存储 |

快路径整体约 **21–22M**；加入轻量预测与 gate 后约 **26M**，不含冻结 VLM。准确参数量应以最终实现统计。

**前向感知。** 参考本体输入为 36 维：

\[
p_t=[
q_7,\dot q_7,\mathrm{TCP}_6,g_1,
\mathrm{wrench}_6,u_{t-1,7},\mathrm{image\ age}_2].
\]

两相机特征各 256 维，本体投影 128 维，融合维度为 \(256+256+128=640\)：

\[
e_t=\mathrm{MLP}_{640\to512\to256}(\cdot),\qquad
b_t=\mathrm{GRU}(b_{t-1},e_t).
\]

固定场景的已知几何、深度或标记点可用于物体位姿估计和毫米尺度 grounding；不能默认语言模型仅看 RGB 就能准确给出机器人坐标。

**快动作。** 给定信念 \(b_t\) 与子目标 \(g_t\)，产生 16 步动作：

\[
A_t=\pi_\theta(b_t,g_t).
\]

以 50 Hz 动作时间格为例，预测窗口为 0.32 秒，非接触阶段只执行前 2–4 步，再观察。接触附近可缩短到 1 步，但真实反应速度仍受相机、编码器和控制延迟限制。低层伺服频率高，不会自动补足陈旧视觉信息。

**动作条件预测。** 每个模型学习：

\[
f_{\omega_i}(b_t,u_t^{exec},\Delta t)
\rightarrow
(\hat b_{t+1},\hat r_t,\hat p_{fail},\hat x_{t+1}).
\]

这里 \(u_t^{exec}\) 是**经过过滤后实际发送给低层控制器的命令**，不是事后观察到的真实末端位移。命令未能完全实现，正是动力学需要学习的内容。

预测“调用快策略”的结果时，应展开其内部闭环：

\[
\hat u_j=\mathcal S(\pi_m(\hat b_j,g),\hat x_j),\qquad
\hat b_{j+1}=f_{\omega_i}(\hat b_j,\hat u_j,\Delta t).
\]

然后计算：

\[
\hat J_m=
\mathbb E_i\!\left[
\sum_{j=0}^{H-1}\gamma^j\hat r_j+
\gamma^H V(\hat b_H)
\right]
-\beta\,\mathrm{Std}_i(\hat R_m).
\]

模型分歧高时缩短预测或回退。分歧只是实用指标，不能直接当作经过证明的失败概率。[PETS](https://arxiv.org/abs/1805.12114)

这里的“慢路径 rollout”指 **VLM 已生成子目标之后的局部规划控制器**。初版无需在每个预测 latent 上重建 RGB、再次调用 VLM。

另一种可行方式是直接学习：

\[
M(b,m,\mathrm{policy\ version})
\rightarrow
(b',R,\tau,\mathrm{success}).
\]

这能直接预测“执行某个策略后怎样”，但策略一更新，option 模型就可能过期，需要版本管理和重新采样。

**5．训练时，哪些梯度应该传到哪里**

建议先交替训练，避免从一开始就让感知、世界模型、策略和 gate 同时漂移。

**快策略先做经验蒸馏。** 采用 noise-to-data 的 flow matching 约定：

\[
A_\tau=(1-\tau)\epsilon+\tau A^*,
\]

\[
L_{\mathrm{FM}}=
\mathbb E\left\|
v_\theta(A_\tau,\tau,b,g)-(A^*-\epsilon)
\right\|^2.
\]

\(A^*\) 来自被环境验证的成功与纠错轨迹。教师动作也可能错误，不能把 VLM 建议无条件当真值。

**世界模型学习真实环境转移。**

\[
L_{\mathrm{WM}}=
\sum_j\alpha_j
\left[
\mathrm{NLL}(\mathrm{sg}(b_{t+j}),\hat b_{t+j})
+\lambda_r(\hat r-r)^2
+\lambda_f\mathrm{BCE}(\hat p_{fail},d)
+\lambda_x\|\hat x-x\|^2
\right].
\]

初期冻结编码器或使用 EMA 目标，并监督任务相关物理量，避免表示退化。成功、失败、停留、错误夹爪时机等数据都要保留。

**Gate 用 SMDP 价值学习。** option 持续 \(n\) 个底层时间步时：

\[
R_t^{(n)}=\sum_{j=0}^{n-1}\gamma^j r_{t+j},
\]

\[
y=R_t^{(n)}
+\gamma^n(1-d)\max_m\bar Q(b_{t+n},m),
\]

\[
L_{\mathrm{gate}}=
\mathrm{Huber}\big(Q(b_t,m),\mathrm{sg}(y)\big).
\]

**思考等待也必须计入 \(n\)**。否则慢系统在仿真中享受了现实中不存在的“免费暂停”。

最干净的 gate 数据来自：克隆同一个完整仿真状态，分别运行快、慢、恢复 option，在相同扰动样本下比较结果。这样可以避免“慢系统只处理困难状态，因此平均分更低”的选择偏差。

**SuperMimic 式策略优化作为后续扩展。** 更新策略时固定世界模型参数，但保留其对状态和动作的 Jacobian：

\[
\frac{d\hat b_{j+1}}{d\theta}
=
f_b\frac{d\hat b_j}{d\theta}
+
f_u\frac{d\hat u_j}{d\theta}.
\]

固定世界模型参数，不等于 detach 整个模型输出。后者会切断动作影响未来奖励的梯度。

但视觉接触操纵中，模型可能预测正确却提供错误梯度。因此我会先验证模型的动作排序和接触区梯度，再引入 BPTT。[SuperMimic](https://arxiv.org/abs/2610.28480)

**7．从 pick-and-place 扩展到 RoboDojo 长程任务，需要增加什么**

我不会让一个 GRU 隐状态承担全部长程记忆。建议显式维护：

- 子目标依赖图与当前节点。
- 对象身份、位置及已完成集合。
- 每个技能的先决条件、后置条件、超时和恢复入口。
- 已验证技能、失败事件及策略版本。

只有后置条件验证通过，才推进任务。例如“放下了”与“物体稳定处于目标容器内”是不同判据。

长程任务对可靠性的要求会急剧提高。如果每个阶段在此前均成功的条件下，都有 99% 成功率，那么 100 个阶段整体只有：

\[
0.99^{100}\approx36.6\%.
\]

要使整体达到 99%，若没有恢复，每个阶段需要约 99.99%。因此，**失败检测与恢复是长程成功率的主要组成部分**。

RoboDojo 适合检验记忆、精度和长程能力，但在某个任务上反复训练后得到的结果，应表述为该任务的专用能力；完整成功率也应与其进度指标区分。[RoboDojo 原始论文](https://arxiv.org/abs/2607.04434)

**8．我会怎样开展实验，以及怎样判断方案失败**

建议按照以下顺序实施：

1. **建立闭环基线。** 固定一个 pick-and-place，明确初态范围、成功判据、时间和自动恢复预算。比较脚本闭环、ACT 与 Diffusion Policy。
2. **加入持续蒸馏。** 慢系统提供探索与纠错，快策略执行，保留失败前沿和恢复数据。
3. **先做规则 gate。** 根据预测误差、传感异常和阶段切换触发接管，检验快慢结构本身是否有收益。
4. **加入小型动作条件预测器。** 先证明其候选排序有效，再把它用于在线规划。
5. **学习 gate。** 用同初态分叉数据训练，并与规则 gate、始终快、始终慢比较。
6. **扩展长程任务。** 增加任务图和独立验证器，再考虑大型 WAM、联合训练与 BPTT。

必须固定或完整报告训练数据、真实交互次数、算力和任务时间预算。主指标包括：整任务成功率、首次成功率、限定重试内成功率、拒绝率、人工接管率、恢复率，以及 p95 延迟。

以下结果应被视为对复杂架构的反证，而不是继续堆模块的理由：

- 简单闭环策略已经达到相同可靠性和更短时间。
- 学习 gate 没有优于清楚的阈值规则。
- 世界模型改善视频预测，却不能改善动作排序。
- 高成功率主要来自无限重试、人工重置或放宽成功判据。
- 新技能提升伴随着旧状态与恢复能力退化。

**我认为最值得验证的研究命题是：在固定场景的长程操纵中，动作条件短期预测与经过实物校准的 option 路由，能否在相同交互预算下，改善“完整任务成功率、耗时、慢模型调用率”的权衡。**

第一轮实验最有价值的结果，应当是明确找出：失败主要来自动作技能、状态估计、阶段判断、模型失准，还是恢复不足。这个诊断会决定下一步是否真的需要更大的模型。

**2．“两个系统融合”与“慢能力变成快能力”，需要分别设计**

这是我认为你当前方案最关键的地方。

假设采用最直接的门控：

\[
m\sim g_\kappa(m\mid h),\qquad
a\sim\pi_m(a\mid h).
\]

慢、快策略彼此独立，慢策略冻结。那么快策略的直接策略梯度是：

\[
\nabla_\theta J
=
\mathbb E\left[
\mathbf1[m=F]\,
\hat A\,
\nabla_\theta\log\pi_F(a\mid h)
\right].
\]

**慢系统接管时，快动作头没有这个梯度。**

因此，门控可以让整体控制器表现很好，同时快策略仍然很弱。它可能学到“困难时永远交给慢系统”，而不是你希望的“困难操作逐渐成为本能”。

已有工作大致提供四种不同工具：

| 融合位置 | 形式 | 能解决什么 |
|---|---|---|
| 控制权选择 | 选择 \(\pi_S\) 或 \(\pi_F\) | 谁来控制、何时接管 |
| 分布融合 | \(q\propto\pi_F\,p_S^\alpha\) | 慢先验怎样改变当前探索 |
| 残差控制 | \(u=u_S+\delta u_F\) | 快策略怎样补偿基础控制 |
| 在线知识转移 | \(L=L_{\rm RL}+\lambda L_{\rm teacher}\) | 教师经验怎样明确写进学生参数 |

这四件事可以结合。**仅有第一件事，不足以说明后面三件事已经发生。**

也要修正一个容易误解的点：分布乘积并不自动避免危险折中。两个高斯技能意见冲突时，乘积仍可能给出错误的中间动作。[关于技能组合中的分歧与修正](https://proceedings.mlr.press/v97/hunt19a.html)

**3．如果“无需采集数据”指不采人工演示，最稳妥的是在线 RL＋同步指导学习**

这条路线有最直接的文献支持。

同一个循环中：

1. 快策略与慢指导共同产生仿真交互。
2. 环境给出成功、失败和成本。
3. 快策略执行的动作用于 RL。
4. 有用的慢指导同时形成在线辅助学习信号。
5. 不建立独立的人工示范采集阶段。

目标可以写成：

\[
L
=
L_{\rm RL}
+
\lambda_t\,
\mathbb E\left[
w(h,a_S)\,
\big(-\log\pi_F(a_S\mid h)\big)
\right].
\]

其中 \(w\) 用于降低错误或无效指导的影响，\(\lambda_t\) 随学生能力调整。连续动作也可以采用明确的分布匹配，但不能对任意确定性 waypoint 凭空定义 KL。

这属于 **RL＋在线知识转移**，无需人工演示，但确实包含非 RL 的辅助损失。Kickstarting、RPD、SAGE 分别提供了这类机制的证据。

**如果你进一步要求“动作策略只能通过 RL 损失更新”，则需要另一种耦合。**

**4．严格仅用 RL 目标时，我更建议研究“慢先验进入快策略的实际采样分布”**

这就是新主图展示的方案。

关键改动是：**慢系统提供探索偏置，最终动作始终经过同一个快策略的可训练 logits。**

以 SimpleVLA-RL 的离散动作管线为例，它将动作表示为 256-bin 分类分布，并以 chunk 与环境交互。可以保留这套管线，增加以下融合。

**慢系统。** 冻结 VLM 根据画面输出局部目标或动作建议。固定适配器把它转换为动作先验：

\[
p^S_j(b)
=
(1-\epsilon)\,
p_{\rm bin,j}(b;\mu^S_j,\sigma_j)
+
\frac{\epsilon}{B},
\qquad B=256.
\]

这里：

- \(j\) 是动作标量在 chunk 中的位置。
- \(\mu^S_j\) 是转换到统一动作尺度后的建议。
- \(\sigma_j\) 控制建议宽度。
- \(\epsilon>0\) 保留探索支持。

**这是一种设计出来的动作先验，不是 VLM 已校准的置信度。**

**快系统。** 快 VLA 或小策略只根据自身部署可得的观测历史产生 logits：

\[
\ell^F_{\theta,j}(b\mid h).
\]

**融合。**

\[
q_{\theta,j}(b\mid h,p^S,m)
=
\operatorname{softmax}_b
\left[
\frac{\ell^F_{\theta,j}(b\mid h)}{T}
+
\alpha_m\log p^S_j(b)
\right].
\]

其中：

\[
\alpha_0=0,\qquad \alpha_1>0.
\]

- \(m=0\)：不调用慢系统，直接运行快策略。
- \(m=1\)：调用慢系统，用其先验引导采样。
- 两种模式的动作都从 \(q_\theta\) 采样。

这样，受到指导的动作也可以给快 logits 合法的奖励梯度：

\[
\frac{\partial\log q_{\theta,j}(Y_j)}
{\partial\ell^F_{\theta,j}(b)}
=
\frac1T
\left[
\mathbf1(Y_j=b)-q_{\theta,j}(b)
\right].
\]

这与“慢系统替学生执行完，再希望学生自动学会”有实质区别。

它与 BCF、MCP 的分布融合思想有关，但**将冻结 VLM 先验接入 SimpleVLA-RL，并证明能够更快形成独立快策略，是需要实验验证的新组合**，不是现有论文已经替你证明的结果。

**5．一体训练时，实际优化对象必须写对**

加入 gate 后，行为策略是：

\[
\mu_{\theta,\kappa}(m,Y\mid h,c)
=
g_\kappa(m\mid h,c)
\prod_j
q_{\theta,j}(Y_j\mid h,p^S,m).
\]

其中 \(c\) 可以包含廉价可得的查询预算、缓存年龄等。

保存的行为概率应为：

\[
\log\mu_{\rm old}
=
\log g_{\rm old}(m\mid h,c)
+
\sum_j\log q_{{\rm old},j}(Y_j\mid h,p^S,m).
\]

重算时必须使用**同一次指导的 prior**，以及相同的温度、指导强度、动作 mask 和有效长度。

这里最容易犯的错误是：

> 动作实际上由慢系统或融合策略生成，却直接填入原始快策略的 `old_logprob`，继续运行原 GRPO。

这会混淆行为策略来源。

还有两个实现细节：

- gate 每个 chunk 只决策一次，不能在每个动作 token 上重复累计同一个 gate 梯度。
- 上述整段联合 ratio，与 SimpleVLA-RL 的逐 token surrogate 不同。可以采用分开的 gate/token surrogate，但应明确算法修改与近似，不能混称完全相同的目标。

调用成本可以进入共同回报：

\[
R
=
R_{\rm task}
-\lambda_q N_{\rm query}
-\lambda_t T_{\rm elapsed}.
\]

慢模型先冻结，是为了减少非平稳性；“一体训练”不要求所有权重同时更新。第一版让快策略与 gate 共享一个交互和回报循环，已经足以检验核心假设。

**6．这个纯 RL 融合方案最可能在哪里失败**

这里必须保持谨慎：**有梯度，不等于慢知识一定会固化到无指导的快策略。**

主要风险有：

1. **先验过强。**  
   \(q\) 接近确定，探索减少，快 logits 的有效梯度也可能很小。

2. **快策略学成了先验的修正器。**  
   guided 表现很好，但去掉先验后行为崩溃。必须始终保留无指导训练与评估。

3. **稀疏奖励仍然无法启动。**  
   VLM 如果也无法产生有用探索，所有轨迹仍全失败。动态采样不会凭空制造第一次成功。

4. **指导让所有轨迹都成功，反而没有组内信号。**  
   纯二元成功奖励下，组内优势可能全部为零。若成功轨迹的调用成本不同，又不能沿用“全成功组全部丢弃”的筛选。

5. **Gate 塌缩。**  
   一直求助会掩盖学生弱点；过早禁止求助会使稀疏成功消失。应保留两种模式的探索机会，并按实际行为分布记录概率。

6. **独立分量先验破坏动作相关性。**  
   每个维度分别加偏置，可能无法表达正确的跨维度、跨时间动作关系。精密接触任务尤其需要检验这一点。

7. **把低熵当成熟。**  
   策略可以非常自信地犯错。BCF 也没有直接把普通动作头方差当作认知不确定性，而是额外使用集成估计。[BCF](https://arxiv.org/abs/2107.09822)

因此，训练中的“成熟”应由 **关掉慢系统、清除教师缓存后的 fast-only 成功率** 定义，不能只看混合系统成功率或慢调用次数下降。

**7．在你的基线上，我建议这样做第一轮实验**

先保留 SimpleVLA-RL 的快 VLA、动作 token 管线和并行仿真框架，避免同时更换成另一套小网络。增加：

- 冻结的慢 VLM。
- 无训练参数的语义动作适配器与先验构造。
- 小型 query gate。
- 正确的融合采样与行为概率记录。

第一轮比较四组：

| 组别 | 用途 |
|---|---|
| 原始快策略 RL | 基线 |
| 慢／快硬切换＋联合 RL | 检验路由本身 |
| 动作先验融合＋RL | 检验不使用模仿损失的耦合 |
| 在线 RL＋教师辅助损失 | 检验显式知识转移是否更有效 |

初始化条件也应分开：已有任务 SFT、通用 VLA 但零任务示范、随机快动作头。否则无法判断收益究竟来自冷启动机制还是已有技能。

主结果应包含：

- **fast-only** 达到目标成功率所需的仿真交互数。
- 同一目标下的 wall-clock、GPU-hours 和 VLM 查询数。
- 混合系统与 fast-only 的成功率差距。
- 撤去或置乱教师建议后的性能变化。

WAM 可以随后利用在线转移训练，用于探索、候选排序或价值估计。**我会先验证融合是否真的加速快策略成长，再加入 WAM**，这样才能解释收益来自哪里。

你这个研究最值得提出的命题是：**慢语义指导能否在无需人工任务示范的在线 RL 中，改善最初的成功探索，并更快形成脱离指导后仍可靠的快速策略。** 这比仅证明“两个系统组合后表现更好”更贴近你想实现的过程，也更有辨识度。
