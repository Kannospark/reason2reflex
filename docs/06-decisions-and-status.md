# 决策与状态记录

本文件防止把讨论中的建议误写成既定方案。状态基于截至 2026-11-11（Asia/Tokyo）的会话；它记录的是设计决策状态，不是软件完成度或实验达成状态。

## 状态定义

| 状态 | 含义 |
|---|---|
| **Confirmed / 已确认** | 用户明确表达的目标、约束或后续澄清。 |
| **Open / 未决** | 讨论没有足够信息确定，或用户尚未作选择。 |
| **Proposed / 提案** | 助手提出的候选设计、实现顺序或评测方法，尚未被实验或用户最终确认。 |
| **Withdrawn / 已撤回或被取代** | 早期表达与后续澄清冲突，或存在已指出的问题，不得继续当作当前方案。 |

“已确认研究目标”不等于“已验证可行”；“提案”不等于“错误”；“未决”也不要求在保存研究记录前全部解决。

## 1. 已确认的研究方向

| ID | 事项 | 当前含义与边界 |
|---|---|---|
| C01 | 固定场景优先 | 用户暂不以跨场景泛化为目标。场景内扰动范围仍需定义。 |
| C02 | 仿真强化学习主线 | 整体基线类似 SimpleVLA-RL 的仿真交互训练框架。复用框架不代表照搬所有初始化条件。 |
| C03 | 指导到成熟策略一体成长 | 慢指导与快策略训练应位于同一个交互过程，避免只展示两个模型轮流控制。 |
| C04 | 无额外人工任务示范采集阶段 | 用户明确希望“通过不用采集数据的强化学习”。RL 仍会产生并使用环境轨迹。 |
| C05 | 慢系统角色 | VLM、理解与直接控制代表初级场景理解和探索。具体模型未定。 |
| C06 | 快系统角色 | VLA 或类似快速策略代表熟悉后的、本能式执行；不限定必须采用 VLA。 |
| C07 | 任务示例 | 可以从 pick-and-place 开始，也关心 RoboDojo 式更长程复杂任务。具体任务未选。 |
| C08 | 融合研究范围 | 除双系统外，也应考察两个技能、控制器、策略或先验的融合。 |
| C09 | 可靠性愿景 | 原始目标包含单场景仿真实物迁移与“100% 成功率”。该目标未被证明，不能写成结果。 |
| C10 | 研究表达要求 | 结合现有研究，以严谨、批判、客观方式分析优缺点及解决办法。 |
| C11 | 图示质量要求 | 论文级方法图；具体计算、模块、数据与梯度路径清楚；PPT 可编辑，并提供 PNG。 |
| C12 | 首版视觉结果不被接受 | 用户明确批评第一版图。修订图尚无用户最终视觉验收。 |

## 2. 仍未决定的事项

| ID | 未决问题 | 为什么影响设计 |
|---|---|---|
| O01 | 是否严格只允许 RL 损失 | “无人工示范”不自动排除在线教师辅助损失；两者不可混为一谈。 |
| O02 | 快策略初始化 | 任务 SFT、通用预训练 VLA、随机动作头代表不同冷启动难度。 |
| O03 | 初始慢系统能力来源 | 冻结通用 VLM、已有 VLA 教师、规则控制器、规划器的能力来源和预算不同。 |
| O04 | 具体机器人、夹爪与传感器 | 决定动作接口、控制频率、接触观测和 sim-to-real 误差。 |
| O05 | 仿真器、任务与场景参数范围 | 决定状态可克隆性、奖励可获得性和评价分布。 |
| O06 | 硬件、GPU 与时延预算 | 决定模型大小、并行环境数、查询成本和快慢时间尺度。 |
| O07 | 动作表示 | 末端位移、关节控制、离散 token、连续 chunk 的选择尚未定案。 |
| O08 | Gate 的职责 | 是纯查询器、控制权选择器、融合强度调节器，还是多种职责的组合？ |
| O09 | Gate 的监督与不确定性 | 熵、模型分歧、价值、失败率与熟悉度都不能直接互换。 |
| O10 | WAM 的具体含义与实现 | 世界模型、动作条件未来预测、视频预测和价值模型并不等价。 |
| O11 | SuperMimic 类机制迁移范围 | 是交替学动力学、想象优化、BPTT，还是仅借鉴整体训练方式？ |
| O12 | 允许的重试与恢复预算 | 决定“单次成功”“预算内成功”和长程任务成功率如何解释。 |
| O13 | “100%”的正式评价协议 | 需要初态分布、扰动、冻结策略、试验数、人工介入与停止规则。 |
| O14 | 长程记忆形式 | GRU/LSTM、显式任务图、事件日志、技能库如何分工。 |
| O15 | 仿真实物迁移流程 | 系统辨识、随机化、真实数据使用范围和部署安全边界未确定。 |
| O16 | 修订图的最终风格与结构 | 现有图是候选方法展示，不应视为已通过用户验收的最终论文图。 |

## 3. 当前保留的候选提案

| ID | 提案 | 状态与注意点 |
|---|---|---|
| P01 | 保留 SimpleVLA-RL 的快 VLA 管线开展首轮实验 | 用于减少同时变化的因素，不是最终架构要求。 |
| P02 | 冻结慢 VLM，训练快策略与小型 gate | 降低非平稳性；“一体训练”不要求所有模型权重同时更新。 |
| P03 | 统一低层动作接口 | 慢建议与快输出使用一致单位、坐标系、时间格及控制器；action trunk 与位移不是同级概念。 |
| P04 | RL 加在线教师辅助损失 | 直接支持知识转移；无需人工示范，但不属于严格只有 RL 损失的路线。 |
| P05 | 慢动作先验与快 logits 融合，仅用 RL 更新 | 实际采样分布包含快参数；需记录正确行为概率，且不保证撤去先验后仍能执行。 |
| P06 | 硬切换作为对照 | 能检验路由收益；不能单独证明慢能力已进入快动作头。 |
| P07 | Gate 评价真实任务收益与调用成本 | 可用 options / SMDP 处理持续动作；等待时间应计入成本和折扣。 |
| P08 | 用 fast-only 表现定义成熟 | 关闭慢系统与教师缓存，单独测试快策略，防止混合表现掩盖依赖。 |
| P09 | 先验证核心融合，再加入 WAM | 降低收益归因难度；WAM 可随后用于探索、排序、价值或动力学学习。 |
| P10 | 小型动作条件预测器先于大型视频模型 | 对固定场景可能更易校验，仍需真实实验比较。 |
| P11 | 短期模型 rollout 和分歧约束 | 限制模型误差累积；模型分歧本身不是校准失败概率。 |
| P12 | 显式任务图、后置条件与恢复入口 | 面向长程任务；结构化状态与时序网络可互补。 |
| P13 | 保留真实失败、恢复和偏离状态 | 避免只学习完美轨迹；如何使用取决于所选 RL 算法。 |
| P14 | 严格区分预测准确、动作排序和有用梯度 | WAM 视频逼真不能替代这些控制层面的验证。 |
| P15 | 动作条件模型固定参数后用于策略优化 | 仅在模型与梯度可靠后考虑 BPTT；固定参数不等于 detach 整个输出。 |

### 候选融合路线的当前关系

```text
用户已确认：同一仿真 RL 循环、无额外人工任务示范采集
                         │
             ┌───────────┴───────────┐
             │                       │
    候选 A：RL + 在线辅助学习   候选 B：先验融合 + RL 目标
             │                       │
    教师能力显式进入快参数       指导改变实际探索分布
             │                       │
             └───────────┬───────────┘
                         │
        必须检验：撤去慢系统后快策略是否真正成熟
```

该分叉记录了未决设计，不表示已经决定同时实现两套完整系统。

## 4. 已撤回、被取代或明确不能沿用的表述

| ID | 原先表达或可能误读 | 当前修正 |
|---|---|---|
| W01 | 先由慢模型采集示范，再以 BC 为主线训练快策略 | 不再作为默认方案。用户澄清以在线仿真 RL 一体成长为主线；BC / 辅助监督只能单独标注为候选或对照。 |
| W02 | 两系统门控后，慢能力会自然进入快策略 | 没有这一保证。硬路由下慢接管步通常不给独立快动作头直接策略梯度。 |
| W03 | 每次调用 VLA 固定奖励 +0.1 是既定设计 | 只是用户提出的问题示例。尚未采纳；可能导致调用或拖延的奖励投机。 |
| W04 | “用 action trunk”与“输出位移”是互斥选项 | 一个是网络实现，一个是动作语义；应在一致控制接口下讨论。 |
| W05 | 每次窗口刷新就等于已保存策略权重丢失 | 对话上下文、运行时状态与长期参数不同，需要分别保存和恢复。 |
| W06 | 100/100 测试成功就证明真实成功概率为 1 | 有限零失败样本不建立绝对保证，应报告协议与统计界。 |
| W07 | SimpleVLA-RL 已证明完全零任务示范冷启动 | 不应如此引用；需要准确区分其初始化与在线 RL 阶段。 |
| W08 | 先前给出的 7B、二千万级快策略等就是最终配置 | 都是参考建议，未被任务、硬件或实验锁定。 |
| W09 | 融合后仍可以直接使用原始快策略的行为概率 | 训练概率应对应实际行为分布；教师或融合动作不能伪装为快策略单独采样。 |
| W10 | 分布乘积或概率融合天然避免冲突动作 | 没有此保证；冲突先验可能产生无效或危险中间动作。 |
| W11 | WAM 预测画面逼真即可指导控制 | 还需要动作条件敏感性、候选排序、接触相关量和必要时梯度的独立验证。 |
| W12 | 修订后的图等于已验证方法或用户已接受的最终主图 | 图是候选方法的表达；尚无实验验证，也未收到用户最终视觉验收。 |

| 版本 | 内容 | 保留与变化 |
|---|---|---|
| v0：用户原始想法 | 单场景 sim-to-real 可靠性；人脑类比；慢探索与快执行；LSTM / Transformer gate；在线 RL；SuperMimic / WAM | 作为原始动机和问题记录保留。 |

## 6. 建议的下一个研究检查点

以下是助手建议的工作顺序，并非用户额外作出的实施承诺：

1. 固定一个任务、初态范围、成功判据和预算。
2. 明确“零人工任务示范”允许哪些预训练模型与在线教师信号。
3. 复现快策略 RL，记录冻结策略的基准表现。
4. 用相同初始化、交互预算和计算报告比较硬路由、先验融合、在线辅助学习。
5. 以 fast-only 学习曲线判定成熟速度，另报混合性能与查询成本。
6. 只有核心融合收益清楚后，再加入 WAM、长程记忆和更复杂 gate。
7. 再开展仿真实物误差辨识、恢复机制与正式可靠性试验。

更完整的动机与讨论演进见 [研究想法与讨论演进](01-idea-and-evolution.md)。
