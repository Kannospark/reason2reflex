# 实验计划、失败判据与开放问题

记录日期：2026-11-11。

**状态：研究计划；尚未实现、尚未训练、尚未运行本文实验。下列数值是评估门槛或示例，不是结果。**

## 1. 主研究问题

在固定场景、无需人工任务示范的在线仿真 RL 中，慢语义理解与动作指导能否：

1. 更快产生第一次有用成功探索。
2. 在相同交互和计算预算下，更快形成独立快策略。
3. 随熟练程度提高，减少慢调用，同时维持任务可靠性。
4. 在迁移到实物后，保留上述收益，而非只在理想仿真中成立。

主要证据应来自学习曲线、明确的行为来源、撤去指导后的能力和实物延迟条件。总体架构像“双系统”本身不是足够的研究结论。

## 2. 第一轮任务与任务契约

建议从一个固定 pick-and-place 实例开始，再增加接触与长程复杂性。具体机器人、场景、传感器、GPU 和仿真器尚未确定，不能预写成既有平台。

每项实验先固定：

| 项目 | 需要写明的内容 |
|---|---|
| 初始状态分布 | 物体位置/姿态、机器人初态、障碍、抓取物数量、相机参数。 |
| 场景内扰动 | 摩擦、质量、接触参数、视觉噪声、遮挡、标定误差、延迟、执行误差。 |
| 成功判据 | 明确几何/状态后置条件、保持时间、完整任务是否结束。 |
| 失败判据 | 掉落、越界、碰撞、过力、超时、不可恢复状态、人工接管。 |
| 预算 | 最长物理时间、慢查询预算、自动重试次数、恢复次数。 |
| 部署信息 | actor、gate、教师分别可获得哪些观测，哪些 privileged 信息仅用于训练。 |
| 评估采样 | 固定测试初态、独立种子、冻结检查点、是否允许在线更新。 |

不追求跨场景泛化，也不意味着测试可以完全排除固定场景中必然存在的扰动。

## 3. 初始化条件必须分层

| 设置 | 含义 | 能支持的表述 |
|---|---|---|
| 任务 SFT warm start | 使用该任务已有监督轨迹，再在线 RL。 | 验证融合机制能否改善已启动策略；不能主张零任务示范。 |
| 通用 VLA，零任务示范 | 保留通用预训练，不使用当前任务动作示范。 | 最贴近“零人工任务示范”的主要候选。 |
| 预训练 VLM + 随机快动作头 | 慢系统有语义先验，快动作头未学当前控制。 | 检验慢指导能否帮助动作冷启动。 |
| 全随机 | 不使用预训练视觉/语言/机器人能力。 | 更强、更不同的命题，当前并非明确要求。 |

同一个方法若使用不同初始化，其数据先验、成功探索难度和 GPU 成本不能混在一条曲线上。SimpleVLA-RL 的任务 SFT 起点应被准确复现，而不是默认为零示范基线。

## 4. 最小对照组

优先保留同一快 VLA、动作接口和并行环境，只更改指导与融合，以便解释原因。

| 组别 | 目的 |
|---|---|
| Fast-only RL | 参考在线强化学习基线。 |
| Slow-only | 测量慢指导本身能做什么、成功率与真实耗时。 |
| 固定概率/固定日程 hard gate | 排除单纯增加教师帮助和探索量的影响。 |
| 规则 gate | 检验学习式 gate 是否优于简单阈值。 |
| 学习式 hard gate + 联合 RL | 测量控制权路由收益；不默认能完成知识转移。 |
| Guided PoE + RL | 检验不使用教师模仿损失的动作先验融合。 |
| RL + 在线教师辅助目标 | 检验显式知识转移是否更快、更稳定。 |

如果预算有限，第一批优先比较 Fast-only、hard gate、guided PoE、在线知识转移四组。WAM 不应作为所有组共同新增的大组件，否则无法识别技能转移的贡献。

## 5. 公平预算与核心指标

至少同时报告四种成本：环境交互数、VLM 查询数、wall-clock、GPU-hours。只比较仿真步数可能掩盖慢指导的巨大计算开销；只比较训练时间又可能掩盖硬件差异。

| 指标 | 解释 |
|---|---|
| 首次成功所需交互量 | 检验慢指导是否改善冷启动。 |
| Fast-only 学习曲线 | 去掉慢系统后，快策略是否真正成熟。 |
| Hybrid 学习曲线 | 整体混合系统的实用表现。 |
| 达到预声明成功门槛的成本 | 可预设 95%/99% 等门槛；这些是门槛，不是已获结果。 |
| 慢调用比例、次数与缓存命中率 | 测量依赖和摊销，区分没有调用与使用陈旧教师缓存。 |
| 完整任务成功率 | 长程场景不能只报某个阶段成功或 progress。 |
| 首次成功率与限定重试内成功率 | 分离基础技能和恢复贡献。 |
| 拒绝率、超时率、人工接管率 | 避免“只统计愿意执行的样本”。 |
| 恢复触发率与恢复成功率 | 解释长程可靠性来源。 |
| 平均与 p95 控制/查询延迟 | 真实部署瓶颈往往来自尾部延迟。 |
| 任务阶段覆盖与失败类型 | 检验成功是否只来自简单初态。 |

若方法提高 environment-step efficiency，却消耗更多 GPU-hours，应按实报告两者，不能只选有利坐标。

## 6. Fast-only 评估契约

成熟的定义不是 gate 更少调用教师，而是快策略在独立条件下更可靠。

每次评估应：

1. 冻结相应模型检查点，不在测试集上继续更新。
2. 禁止慢查询，移除慢建议、子目标缓存和由教师初始化的隐藏状态。
3. 将“无建议”条件设为训练时明确出现过的输入，而不是测试临时制造未知 token。
4. 使用相同测试初态与扰动，分别评估 fast-only 与 hybrid。
5. 限制恢复/重试预算，报告人工接管；不能由后台教师暗中救援。

如果已有任务图或固定用户目标，它可以作为各组共同信息保留；需要撤去的是额外教师指导，而非把任务本身删掉。

Hybrid 成功率持续上升、fast-only 不升，说明改善主要来自援助，不支持“本能形成”的主张。调用率下降、成功率也下降，则不支持成熟带来效率收益。

## 7. 关键消融与可证伪假设

| 问题 | 消融 | 支持或反对什么 |
|---|---|---|
| 语义理解是否有用 | 置乱建议、随机等成本先验、脚本控制先验。 | 排除纯随机探索增加或额外算力解释。 |
| 是否需要学习 gate | 固定日程、规则阈值、学习 gate 同预算。 | 若规则同样好，复杂 gate 的价值不足。 |
| 知识到底怎样转移 | guidance-only、辅助学习-only、联合 RL + 辅助学习。 | 区分探索帮助与参数内化。 |
| Guided PoE 是否依赖 prior | 不同 $\alpha$、prior floor、宽度；训练/评估撤去 prior。 | 检测策略是否只学成了先验修正器。 |
| chunk 长度的影响 | 相同执行周期下改变预测与执行长度。 | 检测开环累积误差、likelihood 方差和 gate 信用分配。 |
| gate 学到什么 | 按阶段、错误类型和训练进度统计调用。 | 不能只用 gate 分类准确率代替成功率。 |
| 指导是否陈旧 | 注入查询延迟、缓存失效、运动后旧建议。 | 检验异步部署与缓存有效范围。 |
| 教师错误能否被克服 | 定量注入偏移、错误子目标或过期建议。 | 检验学生是否能超过或纠正教师。 |
| 是否只是 warm start 好 | 不同初始化条件分别训练。 | 防止把已有任务 SFT 的效果归给慢指导。 |
| WAM 是否必要 | 无 WAM、小结构化模型、视频 WAM 同预算。 | 测量真实增益和成本，而非只看预测视频。 |

## 8. 已知失效与对应处理候选

### 8.1 组内零优势

全失败时没有首次成功信号；全成功且只看二元奖励时也可能没有差异。可记录有效组比例、成功概率区间和拒绝采样成本。

自动课程、中间状态重置或 shaping 可以作为解决候选，但应分别消融和报告。不能以在代码中不断重采样替代对全失败根因的研究。

### 8.2 Gate collapse

一直调用慢系统会让快分支缺少训练覆盖；一直走快路径又可能错过启动成功。候选措施包括最小探索概率、按阶段覆盖、分块更新、调用成本逐步调整与同状态分叉评估。

永久强制 50/50 负载不应成为最终优化目标，因为它可能强迫使用较差分支。最终要优化任务和成本，不是漂亮的调用比例。

### 8.3 行为概率错配

teacher-origin action 被当作学生 on-policy action、重算时改变温度或 prior、gate 概率被每个 token 重复累计，都会使结论难以解释。应先用小型可检查环境验证 likelihood bookkeeping，再扩大训练规模。

需要保存 mode、建议、原始动作变量、mask、行为版本和 old logprob。此处的验证针对算法实现，不代表已有此类代码或测试结果。

### 8.4 强先验与错误自信

强 prior 可能抑制探索，低熵快策略也可能稳定犯错。不能直接把动作方差、VLM 自报置信度或 ensemble 一致性当作真实成功概率。

可比较支持集下限、温度、指导强度上限、校准失败预测与独立验证器。校准需使用与部署扰动相关的数据。

### 8.5 两个策略和 gate 同时变化

非平稳教师、学生和路由会使价值估计与先验有效性漂移。首轮可冻结 VLM 与适配器，使用策略版本、分块更新和目标 critic。全端到端更新是后续实验，而不是“一体训练”的必要定义。

### 8.6 奖励投机

调用正奖励、无限恢复、忽略超时或只计已接受任务，可能得到虚高“成功率”。成功、预算和人工介入规则要在训练前写清，必要时用独立验证器复核。

### 8.7 世界模型被利用

策略可能寻找模型漏洞，预测奖励升高而真实回报降低。候选措施是短期想象、从真实状态重锚、模型分歧限制、真实转移校准和限制想象数据比例。核心检验仍是实际仿真与实物回报。

## 9. WAM 的进入条件

先证明没有 WAM 的融合训练能提升 fast-only 学习速度，再考虑：

1. 动作反事实：同状态下零动作、反向动作、不同幅度是否产生合理差异。
2. 候选排序：预测最高回报的动作是否在真实仿真中更好。
3. 物理量准确性：位姿、接触、夹持与失败事件。
4. 长期误差：预测步数增加时，决策收益是否变差。
5. 梯度有效性：模型建议的局部动作变化是否改善真实回报。
6. 成本收益：新增训练与推理开销是否值得。

视频逼真或 latent loss 下降不能替代这些指标。多步奖励、未来视频和动作控制的联合生成，也不自动代表对给定候选动作具有准确反事实预测。

## 10. 从 pick-and-place 到长程任务

长程实验可逐步扩展为：多物体排序、重复抓放、包含依赖的装配或 RoboDojo 类任务。需要额外定义：

- 对象身份和物体状态更新。
- 子目标先决条件与后置条件。
- 任务进度记忆与已经完成的集合。
- 失败定位与局部恢复入口。
- 阶段成功与完整任务成功的分别统计。

若每阶段在此前成功条件下均有 99% 成功率，100 阶段全部成功约为 $0.99^{100}\approx36.6\%$。因此局部可靠性、失败检测与恢复会成为长程目标的核心，不只是扩大快策略或延长 hidden state。

已知仿真状态可以用于训练时标注阶段，但部署验证器不能依赖实物不存在的 oracle 信息。需要单独衡量验证器误判，因为错误推进任务图会累积成整体失败。

## 11. sim-to-real 评估路线

仿真训练不代表可以跳过实物验证。建议把以下项目分别测量：

| 项目 | 检验内容 |
|---|---|
| 几何与标定 | 相机外参、机器人 TCP、物体位姿与碰撞几何。 |
| 动力学 | 质量、摩擦、夹爪接触、刚度/阻尼与执行延迟。 |
| 感知 | 遮挡、反光、光照、图像年龄、丢帧和异步时间戳。 |
| 动作适配 | 坐标系、单位、饱和、夹爪语义与控制周期。 |
| 慢推理延迟 | 等待期间保持、停止、继续当前 option 的真实后果。 |
| 恢复 | 可观测失败的检测率与回退动作可行性。 |
| 分布匹配 | 随机化范围是否对应真实测得偏差，而非任意范围。 |

“零真实任务演示”可以作为明确目标，但系统辨识、安全检查、标定和真实评估仍然是实物工作。若使用少量真实交互做适应，应报告其数量，并与零适应迁移区分。

## 12. 100% 目标的统计报告

用户的目标是固定场景中的仿真到实物 100% 成功率。实验可追求零观察失败，但必须区分：

1. 某个有限测试集全部成功。
2. 声明分布下成功率的统计下界。
3. 任何物理条件下绝不失败。

有限测试不建立第三项。对冻结策略、声明分布下独立的 $n$ 次试验，全部成功时，单侧 95% 精确二项下界为：

$$
p_L=0.05^{1/n}.
$$

| 零失败试验次数 | 对应的成功率下界约值 |
|---:|---:|
| 100 | 97.05% |
| 299 | 99% |
| 2,995 | 99.9% |
| 29,956 | 99.99% |

这是统计计算示例，不是项目结果。测试中持续改策略、挑选初态、排除失败或择时停止，不能直接套用该下界。实物重复试验还可能存在磨损、温漂和序列相关，需要说明独立同分布假设的适用性。[精确二项区间说明](https://www.itl.nist.gov/div898/software/dataplot/refman2/auxillar/exacbino.htm)

自动重试后的任务成功率与首次执行成功率应分别报告。安全约束保证、拒绝执行和任务完成保证也应分别定义。

## 13. 应当接受的反证

出现以下情况时，应收缩或修改方法，而非继续增加模块：

- 一个简单闭环策略在相同预算下同样可靠、训练更快。
- 学习 gate 没有优于明确的规则 gate。
- Hybrid 显著提升，但 fast-only 没有改善。
- Guided PoE 只有先验存在时有效，撤去就崩溃。
- 在线教师辅助损失明显更有效，而 strict RL 方案没有可解释优势。
- WAM 只能改善预测观感，不能改善候选排序或真实回报。
- “高成功率”主要来自无限重试、人工重置或放宽任务判据。
- 新技能的提升伴随旧状态、失败恢复或困难初态能力退化。

## 14. 尚未解决的决策清单

1. **约束定义**：是否仅要求无人工任务演示，还是还要求零任务 SFT、actor strict RL？
2. **平台**：机器人、仿真器、相机/深度/力觉、控制频率与 GPU 预算是什么？
3. **起始任务**：具体 pick-and-place 的物体、精度、扰动和成功条件是什么？
4. **快策略**：保留原 VLA，还是比较随机小头/小型专用策略？何时做规模实验？
5. **慢输出**：子目标、waypoint、动作 bin prior，还是完整可求密度的低层分布？
6. **融合方式**：hard gate、在线辅助转移、guided PoE 或语义上下文，哪条作为主方法？
7. **查询粒度**：逐 chunk、逐技能、事件触发；缓存何时失效？
8. **指导错误**：如何检测、如何允许学生超过教师？
9. **奖励**：只用终局成功还是加入成本/阶段结构？若加入，如何保持比较公平？
10. **GRPO 改动**：逐 token surrogate、gate 独立目标还是 chunk joint ratio？如何避免重复计权？
11. **冷启动**：慢系统无法带来首个成功时，允许哪些课程和重置机制？
12. **长程状态**：任务图、对象跟踪、恢复和验证器各自如何实现？
13. **WAM 定位**：表示学习、规划排序、critic 目标，还是可微 imagined policy optimization？
14. **实物目标**：测试分布、自动恢复预算、人工接管与所需统计置信度如何声明？

上述问题保留为开放项，不用助手建议替用户提前定案。

## 15. 建议的实施顺序

1. 固定任务契约和预算，复现参考 Fast-only RL。
2. 接入冻结慢 VLM、固定动作适配器和完整 rollout 记录。
3. 运行 hard gate 基线，确认混合控制与概率归属正确。
4. 比较 guided PoE 与在线知识转移，持续测量 fast-only 曲线。
5. 在语义置乱、延迟和教师错误下检验收益来源。
6. 验证学习 gate 是否超过规则与固定日程。
7. 增加长程记忆、恢复与独立后置条件验证。
8. 只有已有证据支持时再加入 WAM、联合训练和更大模型。
9. 校准 sim-to-real 条件，冻结策略后开展明确分布的实物评估。

每步都应留下代码、配置、模型与数据来源、失败日志和真实运行结果。当前仓库阶段是研究档案，尚未进入这些实施步骤。
