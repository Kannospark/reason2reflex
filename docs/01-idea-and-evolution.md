# 研究想法与讨论演进

本文件记录研究发起者当前的目标、原始构想、后续澄清，以及讨论中提出但尚未定案的候选方案。它是研究档案，不是已经实现的方法说明，也不是经过实验验证的论文结论。

- 记录日期：2026-11-11（Asia/Tokyo）。
- 研究范围：固定场景中的机器人操作，从仿真强化学习走向实物执行。
- 当前状态：概念、文献分析与方法设计阶段；本仓库未因此自动获得任何机器人实验结果。
- 本文件是按主题整理的记录，**不是完整逐字会话**。文中短引语保留用户原意；助手建议另行标注。

## 1. 发起者的原始目标

用户最初希望实现：

> “一个在一个场景中（不考虑泛化能力）的能够仿真到实物的100%成功率的方法。”

这一定义有三个重要约束：

1. 优先解决一个明确场景、任务或场景内任务族，而非先追求跨环境泛化。
2. 训练主要发生在仿真中，最终关心实物机器人能否可靠执行。
3. “100%”是原始可靠性愿景。它尚未被改写成某个已经达成的统计结果，也没有被实验支持。

讨论随后区分了三件不同的事：某个有限测试集全部成功；在声明测试分布上具有较高的成功率统计下界；在真实世界所有情况中永不失败。第一件可以直接观察，第二件需要严格的试验协议，第三件不能靠有限次测试证明。**保留原始愿景，并不等于宣称绝对成功保证。**

即使不考虑跨场景泛化，单场景内仍存在标定误差、摩擦变化、延迟、初态扰动、接触和抓取偏差。如何划定允许变化的范围、超时与重试预算，是后续必须明确的实验定义。

## 2. 人脑学习电脑操作的类比

用户的出发点是：人第一次看电脑屏幕，需要先理解画面和手部移动之间的关系；思考后再操作。随着重复交互，操作可以逐渐形成连贯轨迹，熟悉情形下无需每一步都进行显式推理。

用户希望大模型强大的场景理解能力，能够通过交互逐渐转化为职业选手般熟练的操作能力。其关注点还包括：每次新的使用或窗口可能丢失先前经验，因此不能只依赖一次对话中临时保存的信息。

这里的类比承担的是研究动机。它尚不意味着系统需要精确模拟生物大脑，也不意味着 LSTM 就等价于人的长期记忆。后续设计需要分别处理：

- 当前观测和短期历史；
- 任务进度、对象状态与工作记忆；
- 存入策略权重的长期操作能力；
- 可以恢复和审计的轨迹、失败记录与模型版本。

## 3. 用户最初提出的双系统

### 3.1 慢理解与探索

慢系统应理解没见过的画面、场景关系和任务，允许一定思考延迟，再给出动作。用户最初以 Show-Harness 类工作为参照，设想先让模型在仿真中控制机械臂末端进行简单移动。

在这个阶段，VLM 与直接控制表示对场景的初级理解。它们提供探索方向，但不应永久占据每次动作的昂贵决策链。

### 3.2 快速熟练执行

对于已经见过或熟悉的状态，快系统应产生连贯动作轨迹。它可以是 VLA，也可以是其他快速执行策略。

用户随后用“本能行为”说明这个模块：熟悉场景后，不需要太多显式思考也能产出动作。核心诉求并不是必须使用某个名为 VLA 的网络，而是让交互中获得的能力沉淀为高效执行。

### 3.3 最初的门控与时序结构设想

用户提出过两个候选：

- 使用类似 LSTM 的结构，同时训练，并用 gate 决定使用探索系统还是快速执行系统。
- 使用一层 Transformer 专门学习这个分类器。

这些都是候选，不是已经确定的网络结构。尚未确认 gate 的监督信号、时间尺度、是否有强制探索、何时切换，以及是否需要独立的恢复选项。

## 4. 用户最初提出的训练过程

原始训练想法包含以下环节：

1. 对目标场景精确采样或建模，构造仿真环境。
2. 在仿真中使用强化学习，由环境自动给探索结果评分。
3. 在线探索与策略训练同步进行。
4. 参考 SuperMimic 类架构，同步训练能够预测未来多步执行结果的动力学预测器。
5. 使用 WAM 或相关的世界／动作预测能力，提前估计候选动作的未来奖励，指导探索朝高回报方向进行。
6. 考虑将上述预测模块与快速策略一起训练，以加快熟练策略形成。

用户对后两点保留疑问，原文的“（？）”体现出这仍是机制假设。尚未证明：预测器是否足够准确；预测奖励是否能正确排序动作；是否对策略提供可靠梯度；收益是否超过训练和推理成本。

“SuperMimic”“WAM”在用户原话中主要是架构参照。不同 WAM 工作的模型定义和训练目标可能不同，不能默认它们都支持同一种动作反事实预测或可微策略优化。

## 5. 用户明确提出的三个技术问题

### 问题 1：动作输出如何统一

> “末端输出到底是vla的action trunk还是一个位移指示？这两个东西要怎么融合到一块”

用户关心的是慢理解形成的直接位移指令与快执行模块如何共存、如何相互转化。

助手随后指出：action trunk 是网络实现，位移是动作表示，两者不在同一层级。一个 action expert 可以直接输出末端位移序列。因此候选答案是统一动作的单位、坐标系、时间格与控制器接口，而不是将两者当作天然互斥的动作类型。

这一接口方向是助手建议；最终动作表示、是否采用离散 token、是否保留原 VLA 管线，都尚待实验选择。

### 问题 2：慢“大脑”多大

> “大脑部分用多大的模型”

用户尚未给定模型、机器人、GPU 预算或可接受延迟。助手先前提出过从冻结的 3–8B VLM 范围进行比较、以约 7B 起步的建议，也提出过约二千万级的专用快策略。

这些数字是设计起点，不是从任务难度推导出的最优配置，不是现有硬件或实验事实。后续澄清训练基线后，助手建议优先保留基线 VLA 管线，再研究融合，避免同时改变过多因素。这两套参数方案不能混成一套已经定案的模型。

### 问题 3：如何训练选择器，如何评价调用一个策略

用户希望知道：决策器怎样选择位移控制或快速 action；怎样把“当前使用 VLA”本身作为一种可被评估的策略动作；是否可以采用类似“调用 VLA 就给轨迹 +0.1”的奖励。

助手建议过 option / SMDP 的视角，把调用一个闭环控制过程作为持续一段时间的决策，并按实际任务回报、耗时和调用成本评价。固定给某类调用加分只是用户提出的探索性例子，**没有被采纳为最终奖励设计**。

## 6. 任务范围的补充

当助手询问具体任务时，用户补充：

> “比如pick and place这种任务，或者按照robodojo上面的更长程更复杂的任务”

由此确定的是研究可以覆盖抓放，也要考虑更长程、更复杂的任务形态。尚未确定一个具体 RoboDojo 任务、机器人型号、仿真器、相机设置或硬件预算。

对于长程任务，助手提出任务图、对象状态、阶段验证和恢复入口等结构化机制。这些是为满足长程可靠性提出的候选工程设计，不是用户已经指定必须采用的模块。

## 7. 关键澄清：主线是同一仿真循环中的强化学习

用户之后给出了明确的训练基线：

- [SimpleVLA-RL / arXiv:2509.09674](https://arxiv.org/abs/2509.09674)
- 用户给出的原始 PDF 地址：[https://arxiv.org/pdf/2509.09674](https://arxiv.org/pdf/2509.09674)

用户强调：

> “我想一体的训练指引->成熟策略快速成型的方案，通过不用采集数据的强化学习的方式。”

这次澄清是当前设计的优先约束：

1. 以仿真环境的在线强化学习为整体训练骨架。
2. 慢指导和快策略成长应发生在同一个交互过程里。
3. 目标是不依赖额外的人工任务示范采集阶段。
4. VLM / 直接控制承担初期理解与探索；VLA / 快策略承担熟悉后的快速执行。
5. 应研究融合与能力转移本身，而不仅是把两个模型接起来轮流控制。

这里的“不用采集数据”不能被理解为 RL 不产生或不使用数据。仿真 rollout 仍是训练数据；真正需要区分的是人工示范、任务预训练数据、教师在线建议、环境交互和缓存转移。

**尚未确认的边界：** 用户没有在后续消息中明确选择“只能有 RL 损失”，还是允许“以 RL 为主，同时使用在线教师辅助损失”。这两种路线必须保留为不同候选，不能替用户宣布其中一种已经最终通过。

助手也记录了基线边界：其先前分析指出 SimpleVLA-RL 的公开训练流程并非严格的零任务示范冷启动。因此，“复用其在线 RL 框架”与“已经有论文证明从零人工任务示范起步”是两个不同主张。该边界仍应以原论文和实现为准。

## 8. 用户要求扩大融合研究的范围

用户要求检索双系统融合研究，并明确：

> “可以不是这个系统而是类似两个技能的融合。”

因此相关研究不应只限于名称包含 dual-system 或 VLA 的论文，还应覆盖：

- 慢搜索与快策略的迭代；
- 在线教师指导与学生强化学习；
- 两个控制器的概率分布融合；
- 技能组合、共享先验与残差控制；
- 层次强化学习、options 与终止／选择学习；
- 规划结果如何转化为反应式策略。

助手在后续回答中按这些机制组织过 Expert Iteration、Kickstarting、Bayesian Controller Fusion、Distral、MCP、Composable Deep RL、Option-Critic、RPD、SAGE 与 Guided Policy Search 等研究。它们的作用是提供设计启发和可对照的机制，并不意味着任何单篇已经验证了本项目完整方案。

## 9. 助手第一次方案的偏差与修正

最初的助手分析提供了闭环控制、慢／快／恢复 options、世界模型、持久记忆和统计可靠性等建议，也把“慢系统产生经验，再做 BC / flow matching 蒸馏”放在较突出的位置。

用户澄清后，助手承认这一表达过度偏向了示范与蒸馏，未准确突出用户要求的在线 RL 主线。由此修正为：

- 主问题是慢指导如何在同一 RL 循环中改善快策略学习。
- 纯路由不等于知识转移。
- 人工演示不是默认前置条件。
- BC / 在线辅助监督只能作为明确标注的候选或对照，不能替换用户的主线。
- 更换快网络、添加复杂 WAM、增加 BPTT，都不应先于核心融合机制的验证。

修正并不意味着所有早期建议都被否定。动作接口一致性、接触控制、延迟建模、恢复、严格测试协议仍与目标相关；被撤回的是把它们与某套具体结构混写为已经确定的方法。

## 10. 后续提出的两条候选路线

以下均为**助手提出、用户尚未明确选定**的方法设计。

### 路线 A：在线 RL 加在线教师辅助学习

快策略在仿真中学习任务回报，同时对有用的慢教师建议施加适度辅助学习。无需人工录制任务示范；教师建议在交互时产生。

候选形式：

\[
L=L_{\mathrm{RL}}+\lambda_t L_{\mathrm{teacher}}.
\]

这条路线对“慢能力写入快参数”的机制更直接，但包含非 RL 的辅助损失。教师错误、权重退火、学生能否超越教师仍需研究。

### 路线 B：慢动作先验进入实际采样分布，仅用 RL 目标更新动作策略

慢系统形成动作先验，快系统产生动作 logits，实际行为分布由两者组合：

\[
q_\theta(a\mid h,p^S,m)
\propto
\exp\!\left(\ell^F_\theta(a\mid h)/T\right)
\left(p^S(a)\right)^{\alpha_m}.
\]

其中不查询时 \(\alpha_0=0\)，查询时 \(\alpha_1>0\)。最终动作始终从包含快参数的行为分布采样，使受指导的交互仍能给快策略带来合法的奖励梯度。

这条路线需要正确记录融合后的行为概率，不能用原始快策略概率假装动作由它单独产生。即使梯度正确，也不保证撤去先验后快策略自然成熟；它可能只学成一个依赖先验的修正器。

两条路线均应与“原始快 RL”和“慢／快硬切换”比较。当前尚无实验说明哪条更优。

## 11. 成熟策略的判定

助手提出的关键评价建议是：

> 快策略是否成熟，应由关闭慢系统、清除教师缓存后的独立执行表现判断。

理由是混合系统高成功率或查询次数减少，不能单独证明能力已经进入快策略。后续实验应同时报告：

- 混合系统成功率；
- fast-only 成功率；
- 达到目标 fast-only 成功率所需的环境交互数；
- wall-clock、GPU-hours 与慢模型调用数；
- 对错误、缺失或置乱指导的敏感性。

这是一条候选评估原则，不是本仓库已经完成的实验结果。

## 13. 本仓库应该保存的当前认识

当前最稳定的研究主线是：

> 在固定场景的仿真在线强化学习中，让慢系统帮助启动理解与探索，并将交互收益转化为能够独立执行的快速策略；最终研究其仿真实物迁移与可靠性。

用户明确的要求是研究完整、批判、客观，要结合已有研究分析好处、坏处和解决方法。助手提出的架构、参数和损失只能作为研究候选，必须与原始意图区分。

现阶段不能宣称已经实现：零示范冷启动、100% 实物成功、经过校准的风险 gate、准确的 WAM 反事实能力，或慢知识到快能力的有效转移。

当前确认、未决、提案与撤回事项见 [决策与状态记录](06-decisions-and-status.md)。
